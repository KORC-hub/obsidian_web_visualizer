# Ingenieria de requerimientos

La ingeniería de requerimientos o también llamado elicitación de requerimientos, es el proceso por medio del cual se **identifican las necesidades del cliente** para el desarrollo de software, es importante hacer bien esto ya que **los problemas en esta esta etapa del ciclo de vida del software, afecta directamente las demás etapas**, para llevar esto a cabo se hacen **reuniones** dado que se requiere de **comunicación** continua con el **cliente y los stakeholders.**

Los encargados de hacer este proceso deben hacer uso de diferentes **técnicas** para identificar correctamente las necesidades del cliente y el **impacto** que el desarrollo de la herramienta puede generar sobre las personas y la compañía en general.

# Tipo de requerimientos

| Funcionales | No funcionales |
| --- | --- |
| funcionalidades que tendrá la herramienta de software o la comunicación que el software puede tener con otros sistemas | características o propiedades que debe tener el sistema |

# Tecanicas

Para hacer la elicitación de requisitos se **recomienda utilizar y combinar diferentes técnicas** que permitan extraer del cliente del proceso y de los stakeholders la **información necesaria para el desarrollo del proyecto.**

- Entrevistas - Cuestionarios
- Analisis de sistemas existentes
- LLuvia de ideas
- Prototipo
- Casos de uso
- Observaciones
- Estudio de documentacion
- Taller de trabajo

# Impact map

Los mapas de impacto son simples y son un **acercamiento de lo que se quiere conseguir** con un proyecto, es por esto que son **visuales e intuitivos**, rápidos de dibujar y accesibles tanto para gente de negocio como el equipo técnico.

| ¿Porque? | ¿Quien? | ¿Como? | ¿Que? |
| --- | --- | --- | --- |
| Los **objetivos** del proyecto y las **metas** que se tienen al implementarlo. Este debe de ser **especifico, medible, alcanzable, relevante y temporal** | Las personas que **afectan** o son afectados por el mismo. | Identifica el **impacto que tienen los stakeholders** sobre el proyecto y **como el sistema puede ayudarlos para cumplir** los objetivos del negocio. | Que se debe desarrollar para ayudar a las personas a cumplir con los objetivos trazados. |

# User story map

### User story (using three C)

- **C**arta: Determina el usuario la funcionalidad que quiere y el beneficio que obtendrá de esta.
- **C**onversación: Describe la funcionalidad que se espero obtener al final de la historia (regularmente definida con anticipation entre el product owner y algún stackholder y refinada posteriormente en conjunto con el equipo de desarrollo).
- **C**onfirmación: Se pasa por criterios de aceptación como que condiciones deben de cumplirse para que la historia se de por terminada.
